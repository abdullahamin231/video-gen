# Chat transport

Use [orchestrator.md](orchestrator.md) for the production contract. The chat is the workspace; the CLI
tracks the project. Research, writing, direction and review follow task briefs, not a separate T3 creative method.

Create the agreed project and run `npm run video -- next --project <slug>`. When it prints delegation
arguments, pass them to the available task tool. Respect tracked open tasks; after they finish run
`delegated --project <slug>`. A fresh independent reviewer must not be a producer of that work.
Model choices use the live capability catalog and explicit user settings.

For human checkpoints, `watch --project <slug>` serves the current artifacts. Use its printed URL or the
configured review address; do not assume a particular machine, tailnet hostname or HTTPS port. Record
exact decisions using the CLI's requested quote. `stage-bar --project <slug>` is an optional progress view.

A user status question does not restart production. Apply new direction to current work and continue.
Report missing tools, inaccessible evidence or failed commands precisely; do not fabricate their output.
