# Hands-on app review editorial personality

Use this for actually testing, demonstrating, touring or reviewing an application. A conceptual explanation of software is still an explainer; this profile requires real interaction. Identify the installed version/build and available account capabilities. Explore and test first; write the verdict and narration from observed results afterward. Do not script a successful workflow and fabricate UI to match it.

Create a feature inventory with tested, partly tested, unavailable and out-of-scope states. Plan realistic tasks and important failure cases. Preserve evidence for claims. Use a clean test workspace, demo data and appropriate authorisation. Do not expose tokens, private conversations or unrelated commercial media in raw recordings.

For a comprehensive T3 Code review, consider projects, conversations, model selection, editing, terminal/tests, browser tools, delegated work, worktrees, reviews and settings where the installed build exposes them. Never claim every feature or platform was tested without inventory evidence. Test limitations belong in the review.
